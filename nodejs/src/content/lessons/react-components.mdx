## Інтерфейс із невеликих частин

Компонент React — функція, яка отримує `props` і описує результат відображення. Це схоже на чисту функцію: однакові вхідні дані дають однакову розмітку. Не змінюй отриманий масив під час рендеру; якщо потрібне сортування, створи копію. Така межа робить поведінку зрозумілішою й тестованою.

```tsx
type Topic = { id: string; title: string };
function TopicList({ topics }: { topics: readonly Topic[] }) {
  if (topics.length === 0) return <p>Тем поки немає</p>;
  return <ul>{topics.map(topic =>
    <li key={topic.id}><a href={`/topics/${topic.id}`}>{topic.title}</a></li>
  )}</ul>;
}
```

Ключ `key` повинен представляти **ідентичність даних**. Номер позиції часто змінюється після сортування чи видалення, тому може прив’язати внутрішній стан до іншого рядка. Стабільний `id` лишається з елементом. Ключ потрібен React для узгодження списків, а не відображається у DOM як звичайний атрибут.

Батьківський компонент вирішує, які дані передати, дочірній відповідає за свою частину інтерфейсу. Якщо різні місця сторінки потребують тієї самої поведінки, виділи компонент, але не створюй абстракцію заради одного виклику. Відділяй стани «даних немає», «завантаження» та «не вдалося завантажити»: вони означають різні дії для користувача.

Тест нижче перевіряє готову HTML-розмітку компонента. Він не охоплює поведінку браузера та роботу клавіатури, тому додатково перевір компонент у сторінці. Так поєднуються швидка локальна перевірка й реальна взаємодія.
