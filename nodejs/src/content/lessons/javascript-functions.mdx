## Функція як контракт

Параметри описують вхід, return — результат. Якщо return відсутній, результатом є undefined. Іменована функція зручна у stack trace; анонімні й стрілкові функції часто передають як callbacks. Вони залишаються звичайними значеннями: їх можна покласти в масив, повернути або передати іншій функції.

~~~js
function applyTwice(value, transform) {
  return transform(transform(value));
}
console.log(applyTwice(3, n => n + 2)); // 7
~~~

Тут transform викликається всередині applyTwice. Передаємо саму функцію, а не результат її завчасного виклику. Ця різниця повертається в обробниках подій, middleware та задачах черги.

## Побач виклики в стеку

Уяви, що кожна функція, яка ще працює, лежить на стосі карток. Першу кладе `main`, поверх неї `applyTwice`, поверх останньої — `addTwo`. Зупинившись у `addTwo`, ти бачиш її зверху, а під нею тих, хто чекає на її результат.

~~~js
function addTwo(n) {
  debugger;
  return n + 2;
}

function main() {
  console.log(applyTwice(3, addTwo));
}

main();
~~~

Додай цей фрагмент одразу під `applyTwice` у файлі `stack.js` і запусти його через debugger. На першій зупинці в `addTwo` перевір значення `n` і три імена в **Call Stack**. Натисни Continue, подивись на `n` під час другої зупинки. Перший `addTwo` встиг повернути результат і вийти зі стеку, перш ніж зайшов другий. В обох зупинках під `addTwo` чекають `applyTwice` і `main`.

## Лексична область видимості

Доступ до змінної визначає місце оголошення функції. let і const мають блокову область; до ініціалізації змінну читати не можна. У циклі з let кожна ітерація отримує власне прив’язування. Оголошення через var має інші правила області та підняття, тому під час читання старого коду перевіряй його уважно.

~~~js
function makeCounter() {
  let count = 0;
  return () => {
    count += 1;
    return count;
  };
}
const first = makeCounter();
const second = makeCounter();
console.log(first(), first(), second()); // 1 2 1
~~~

Виклик makeCounter створює локальну змінну. Повернена функція продовжує мати до неї доступ після завершення зовнішнього виклику. Це замикання. Кожен окремий виклик фабрики створює незалежний стан; два посилання на одну повернену функцію спільно використовують її стан.

## Керований стан

Замикання корисне для лічильників, конфігурації й адаптерів. Однак прихований змінний стан ускладнює повторюваність. Для обчислення суми або перевірки даних віддавай перевагу чистим функціям: однаковий вхід дає однаковий вихід без зміни зовнішнього світу.

У лабораторній стан навмисно потрібний, але доступний лише через три операції. Перевіряй інваріант перед зміною: якщо наступне значення виходить за безпечний цілий діапазон, поточне має залишитися незмінним.

Зверни увагу на життєвий цикл. Замикання утримує доступні йому об’єкти, поки на саму функцію існує посилання. Великі масиви в довгоживучих callbacks можуть непомітно збільшувати використання пам’яті.
