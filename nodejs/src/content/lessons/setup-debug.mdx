## Помилка починається з відтворення

Налагодження — перевірка гіпотез про стан програми. Замість випадкової заміни рядків запиши вхідні дані, очікуваний результат і фактичний результат. Потім скороти приклад до мінімального випадку, який усе ще відтворює проблему. Так зменшується кількість можливих причин.

Розглянь підрахунок суми в копійках:

~~~js
function total(items) {
  let sum = 0;
  for (const item of items) {
    sum = String(sum) + item.priceCents * item.quantity;
  }
  return sum;
}
console.log(total([{ priceCents: 125, quantity: 2 }]));
~~~

Початковий нуль стає рядком, тому додавання виконує конкатенацію. Постав breakpoint на присвоєнні та перевір значення і тип sum до та після кроку. Виправлення повинно відновити числовий інваріант: після кожної ітерації сума є цілим невід’ємним числом.

## Як читати debugger

Breakpoint зупиняє виконання перед інструкцією. Step over виконує поточний виклик без входу всередину; step into переходить у функцію; call stack показує шлях до поточного місця. Watch обчислює вираз у поточному контексті. Якщо вираз має побічну дію, саме спостереження може змінити програму, тому починай із простих значень.

Запуск node --inspect-brk app.mjs дозволяє під’єднати debugger і зупинитися перед початком. У редакторі обирай той самий файл та робочу папку, що й у звичайному запуску.

## Тест зберігає знайдену причину

~~~js
import test from 'node:test';
import assert from 'node:assert/strict';
test('дві одиниці товару', () => {
  assert.equal(total([{ priceCents: 125, quantity: 2 }]), 250);
});
~~~

Тест має падати через початкову помилку й проходити після виправлення. Перевір також порожній кошик, кілька позицій і неправильні дані. Для грошей тут використовуємо цілі копійки; безпечність арифметики перевіряємо через Number.isSafeInteger. Це не універсальна модель фінансів, але точний контракт цієї вправи.

Не приховуй виняток порожнім catch. Поясни, яке значення порушило очікування, виправ причину та повторно запусти весь набір перевірок.
