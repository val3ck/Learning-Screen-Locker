## Інтерфейс починається зі змісту

Браузер читає HTML як структуру, а не як картинку. Заголовок називає розділ, список пов’язує елементи, кнопка виконує дію, посилання веде в інше місце. Ці значення допомагають і клавіатурі, і допоміжним технологіям. Застосування `div` для всього приховує зміст, тому почни з питання: **що це за елемент і як ним користуватися?**

```html
<main>
  <h1>Мої теми</h1>
  <ul><li><a href="/topics/async">Асинхронність</a></li></ul>
  <button type="button">Додати тему</button>
</main>
```

У формі `label` має вказувати на `id` поля, а повідомлення про помилку — бути доступним після відправлення. Таблиця підходить для порівняння даних; список — для переліку, який читають послідовно. Для дії використай `button`, для навігації — `a`. У React ці елементи виглядають знайомо, але `class` у JSX записують як `className`.

CSS описує представлення. Почни з читабельної ширини, достатнього контрасту та логічного потоку. Сітка може перетворитися з двох колонок на одну за вузького екрана. Перевір, чи порядок фокусу відповідає порядку читання, а текст не зникає при масштабуванні. Стан `:focus-visible` показує, де зараз клавіатура.

У лабораторній ти повернеш React-елемент із семантичною карткою. Тести перевірять структуру та безпечне відображення даних. Додатково відкрий сторінку без CSS і пройди її клавіатурою: цей дослід покаже те, чого не видно в скриншоті.
