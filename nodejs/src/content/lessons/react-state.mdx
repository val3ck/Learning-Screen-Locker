## Інтерфейс реагує на події

Звичайна змінна всередині компонента перестворюється під час рендеру. `useState` зберігає стан між рендерами й повідомляє React, що після події інтерфейс треба оновити. Стан має представляти мінімум інформації, потрібної для відображення. Значення, які можна обчислити з інших даних, зазвичай простіше обчислювати під час рендеру.

```tsx
const [selectedIds, setSelectedIds] = useState<string[]>([]);
function toggle(id: string) {
  setSelectedIds(previous => previous.includes(id)
    ? previous.filter(value => value !== id)
    : [...previous, id]);
}
```

Форма оновлення через `previous` особливо важлива, коли кілька подій надходять поспіль. Пряме `selectedIds.push(id)` змінює попередній масив і приховує факт зміни від міркування про програму. Створи новий масив або об’єкт. Це не означає копіювати весь застосунок; оновлюй лише змінену частину структури.

Обробник події має описувати дію користувача. Наприклад, `onClick={() => toggle(topic.id)}` передає функцію, яку React викличе пізніше. Запис `onClick={toggle(topic.id)}` викликає її під час рендеру. Якщо кілька компонентів повинні бачити той самий вибір, перемісти стан до найближчого спільного батька й передай значення та обробники через props.

У лабораторній логіка перемикання винесена в чисту функцію. Її легко перевірити без браузера. У поглибленні ти підключиш цю функцію до React-компонента і побачиш, як стан стає видимим на екрані.
