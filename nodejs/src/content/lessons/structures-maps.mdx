## Пошук і структура даних

Якщо для кожного замовлення шукати користувача через users.find, виникає повторне сканування колекції. Для n замовлень і m користувачів це до O(n·m) перевірок. Одноразова побудова Map за ідентифікатором дозволяє відокремити підготовку від запитів.

~~~js
const users = [{ id: 'u1', name: 'Іра' }, { id: 'u2', name: 'Оля' }];
const byId = new Map(users.map(user => [user.id, user]));
console.log(byId.get('u2').name); // Оля
console.log(byId.has('missing')); // false
~~~

Map підтримує ключі різних типів і зберігає порядок вставлення. Стандарт вимагає в середньому сублінійний доступ; конкретна реалізація зазвичай використовує хеш-таблицю або подібну структуру. Не описуй усі можливі операції як гарантований найгірший O(1).

## Дублікат є рішенням контракту

Конструктор Map у прикладі мовчки залишить останнє значення для повторного ключа. Іноді це бажано; для індексу унікальних користувачів може приховати помилку даних. У лабораторній дублікати відхиляються. Для групування навпаки треба накопичувати всі записи під одним ключем.

~~~js
const tags = ['api', 'node', 'api'];
const unique = [...new Set(tags)];
console.log(unique); // ['api', 'node']
~~~

Set зберігає унікальні значення. Два окремі об’єкти з однаковими полями залишаться різними значеннями, бо порівнюються їхні посилання. Для дедуплікації об’єктів спочатку визнач бізнес-ключ. Також пам’ятай про різницю між рядком '1' і числом 1.

## Об’єкт чи Map

Звичайний об’єкт природний для запису з відомими полями: ім’я, статус, дата. Map природна для динамічного індексу. Ключі на кшталт __proto__ не перетинаються з прототипом Map, якщо використовувати get/set.

Побудований індекс утримує посилання на записи. Зміна запису буде видима через індекс. Якщо джерело змінило ідентифікатор, індекс автоматично не перебудується. Визнач життєвий цикл: побудувати для незмінного snapshot, оновлювати разом із джерелом або створювати заново.

Вправу перевіряй на порожньому наборі, дублікатах, незвичних ключах та збереженні порядку. Оптимізація має зберігати правильність даних.
