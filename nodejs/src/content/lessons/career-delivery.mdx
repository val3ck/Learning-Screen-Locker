## Код має бути зрозумілим наступному розробнику

У реальній задачі важливий не лише правильний результат. Колега має відтворити запуск, побачити, яку поведінку змінено, які перевірки виконані та які обмеження відомі. README відповідає на питання: що це за сервіс, які передумови, як запустити, перевірити й налаштувати без секретів. Короткий опис PR пов’язує проблему з результатом і додає перевірку.

```text
Проблема: повторний webhook створював два повідомлення.
Зміна: один idempotency key на логічну подію.
Перевірка: unit + integration, дубль та відмова перед ack.
Обмеження: зовнішня пошта може прийняти запит і не відповісти.
```

Під час code review читай не лише стиль. Перевір шлях помилки, власність ресурсу, валідацію на межі, транзакцію та очищення ресурсів. Якщо AI-асистент запропонував код, спочатку порівняй його з вимогами, запусти тести й досліди незвичайні гілки. Впевнено написаний код може пропустити важливий інваріант.

Логи допомагають підтримувати сервіс, але можуть розкрити пароль, токен або персональні дані. Придумай безпечну структуру події, залишивши кореляційний id, тип операції та категорію відмови. У лабораторній ти реалізуєш очищення полів лога перед відправленням. Це невелика самостійна задача, яку легко захистити конкретними тестами.

Після роботи спробуй усно пояснити зміни за дві хвилини: вихідна проблема, причина, рішення, тест і компроміс. Таку навичку перевіряють на співбесіді та щодня використовують у команді.
