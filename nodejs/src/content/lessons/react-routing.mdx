## Адреса — частина інтерфейсу

Коли людина відкриває тему, змінюється не лише вміст, а й контекст навігації. URL дає змогу зберегти посилання, оновити сторінку й скористатися кнопкою «Назад». Для маленького клієнта достатньо кількох маршрутів; зі зростанням інтерфейсу застосовують роутер, який зіставляє шлях і компонент.

```tsx
// Ідея декларативного маршруту
<Routes>
  <Route path="/topics" element={<TopicIndex />} />
  <Route path="/topics/:id" element={<TopicDetails />} />
</Routes>
```

`/topics/:id` містить параметр, який прийшов з URL. Він є зовнішнім вводом: перевір довжину, форму та декодування до запиту API. Не припускай, що всі старі посилання ведуть до наявних ресурсів. Для невідомого id покажи зрозуміле повідомлення й шлях до списку.

Клієнтський роутер змінює вміст без повного перезавантаження сторінки. При звичайній схемі URL хостинг має віддавати сторінку застосунку і для прямого `/topics/123`; на статичному хостингу це потребує правила fallback. Hash-маршрут зберігає шлях після `#` і може працювати без такого правила. Обидва варіанти мають чітку семантику переходу та доступну назву сторінки.

У лабораторній ти реалізуєш невеликий розбір маршруту без бібліотеки, щоб зрозуміти механіку. У власному React-клієнті застосуєш готовий роутер. Не сприймай regex маршруту як авторизацію: доступ до ресурсу перевіряє сервер.
