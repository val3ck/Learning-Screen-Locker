## Один стек не означає одну операцію

JavaScript виконує поточну ділянку коду через стек викликів. Середовище Node організовує готові I/O-події, таймери та іншу роботу. Довге синхронне обчислення займає стек і затримує обробку інших запитів. Ключове слово async саме по собі не переносить CPU-роботу в інший потік.

~~~js
console.log('A');
Promise.resolve().then(() => console.log('B'));
queueMicrotask(() => console.log('C'));
console.log('D');
setTimeout(() => console.log('T'), 0);
// A, D, B, C, T
~~~

Першими виконуються синхронні A і D. Обробники Promise та queueMicrotask чекають звільнення поточного стека; у цьому прикладі вони додані в порядку B, C. Таймер стає можливим пізніше. Значення 0 означає мінімальну затримку планування, а не точний час запуску.

## await має межі

await зупиняє поточну async-функцію, а не весь процес. Продовження після вже виконаного Promise потрапляє до microtasks. Нескінченний ланцюжок microtasks може затримувати інші події, тому await Promise.resolve() не є універсальним способом дати виконатися таймеру або I/O.

Node має окремі фази event loop та спеціальну чергу process.nextTick. Порядок setImmediate і setTimeout залежить від контексту запуску; не будуй бізнес-контракт на випадково побаченому порядку двох таких callbacks. У коді краще явно поєднати залежні операції через Promise.

## Порції та справжній паралелізм

Якщо велике завдання можна розділити, обробляй обмежену порцію й явно повертай керування event loop. Для важких CPU-обчислень розглядають worker threads; порціонування лише покращує можливість обслуговувати інші події, але не зменшує загальний обсяг обчислень.

У лабораторній після кожної повної порції викликається переданий yieldNow, крім останньої. За замовчуванням це Promise навколо setImmediate. Тест передає контрольовану функцію та перевіряє послідовність без очікування довільної кількості мілісекунд.

Параметр розміру порції теж є частиною контракту. Нуль або від’ємне значення може зламати планувальник, тому відхиляй його до початку обробки.
