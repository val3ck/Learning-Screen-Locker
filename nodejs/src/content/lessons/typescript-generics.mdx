## Узагальнення зберігає залежність

Generic потрібен, коли алгоритм однаковий для різних даних, а зв’язок типів має залишатися точним. Функція групування не повинна знати поля користувача чи товару. Вона отримує спосіб дістати ключ, а TypeScript зберігає типи елемента та цього ключа.

```ts
function first<T>(items: readonly T[]): T | undefined {
  return items[0];
}

const user = first([{ id: 1, name: 'Оля' }]);
// user: { id: number; name: string } | undefined
```

`T` позначає конкретний тип цього виклику. Для масиву користувачів результат залишається користувачем; для масиву чисел — числом. Union у результаті чесно описує порожній масив. Повернення `any` втратило б цей зв’язок та дозволило викликати неіснуючий метод без корисної помилки редактора.

## Обмежуй лише потрібне

```ts
function keyOf<T, K extends keyof T>(value: T, key: K): T[K] {
  return value[key];
}

keyOf({ id: 3, title: 'Книга' }, 'title'); // string
```

Тут обмеження `keyof T` потрібне: алгоритм читає поле об’єкта. У групуванні ключ повертає передана функція, тому елемент може бути довільним. Для навчальної сигнатури ключ обмежений `PropertyKey`: рядком, числом чи symbol. Сам `Map` підтримує й об’єктні ключі, але тоді рівність визначається посиланнями; таке розширення потребує окремого рішення контракту.

Порівняй `Map` зі звичайним об’єктом: у `Map` числовий ключ `1` зберігає свій тип і відрізняється від рядка `'1'`. Порядок ключів відповідає першій вставці. Це зручно для групування, яке має зберегти порядок появи груп.

Параметр `readonly T[]` означає обіцянку не змінювати вхідну колекцію. Нові масиви всередині `Map` належать результату, але самі елементи залишаються тими ж об’єктами. Це поверхневе групування, а не глибоке копіювання.

У практиці перевір не лише правильні назви типів. Передай порожній масив, повторні ключі та symbol. Потім наведи курсор на результат у редакторі й переконайся, що конкретні типи збережені без явного `any`.
