## Promise представляє майбутній результат

Promise може бути pending, fulfilled або rejected. Функція, передана його конструктору, виконується синхронно; обробники then і catch виконаються пізніше. Async-функція завжди повертає Promise: return стає виконаним результатом, а throw — відхиленням.

~~~js
async function loadPair(load) {
  const first = await load('a');
  const second = await load('b');
  return [first, second];
}
async function loadPairConcurrently(load) {
  return Promise.all([load('a'), load('b')]);
}
~~~

Перша версія запускає b після завершення a. Друга запускає обидва виклики перед очікуванням спільного результату. Promise.all зберігає порядок входу, навіть якщо b завершився першим. Він відхиляється, щойно одне відхилення визначить результат, але сам не скасовує інші операції.

## Політика помилок

Promise.allSettled чекає завершення всіх операцій та повертає окремі статуси. Promise.any шукає перше успішне завершення. Promise.race приймає перший успіх або помилку. Обирай за бізнес-контрактом, а не за коротшим синтаксисом.

Не запускай async-callback у forEach, очікуючи, що зовнішня функція дочекається його. Для послідовності використовуй цикл з await, для обмеженої групи — явний планувальник. Перехоплюй помилку на рівні, де можеш ухвалити рішення; випадковий catch із поверненням undefined перетворює збій на схоже на успіх значення.

## Обмежена конкурентність

Promise.all для тисяч запитів може перевантажити зовнішній сервіс або connection pool. Ліміт означає число одночасно активних операцій, а не кількість запитів за секунду. Rate limiting є окремим завданням.

Створи кілька worker-функцій зі спільним індексом наступної позиції. Кожна забирає індекс до свого await, запускає операцію та зберігає результат саме за цим індексом. У цьому однопотоковому JS-коді між читанням і збільшенням індексу немає await, тому ділянка не переривається іншою worker-функцією.

У лабораторній перша помилка зупиняє видачу нових позицій після її спостереження. Уже розпочаті операції можуть продовжуватися; для їх реального скасування потрібна підтримка AbortSignal, яку розглянемо далі.
