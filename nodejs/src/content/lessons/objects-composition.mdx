## Залежність має бути видимою

Код ціноутворення потребує даних каталогу та правила знижки. Якщо він сам читає глобальну базу, знаходить конфігурацію й відправляє HTTP-запит, навіть простий тест вимагає багато підготовки. Можна передати необхідні можливості як функції.

~~~js
function createQuote({ getPrice, discount }) {
  return function quote(sku, quantity) {
    const subtotal = getPrice(sku) * quantity;
    return subtotal - discount(subtotal);
  };
}
const quote = createQuote({
  getPrice: sku => ({ book: 25000 })[sku],
  discount: subtotal => Math.floor(subtotal / 10)
});
console.log(quote('book', 2)); // 45000
~~~

Фабрика зберігає залежності в замиканні. Під час тесту getPrice може читати Map; у реальному адаптері — кеш чи базу. Контракт функції важливіший за конкретну реалізацію. Наведений приклад поки не перевіряє відсутній товар і межі знижки: ці перевірки додаємо у вправі.

## Розділяй рішення й механізм

Бізнес-правило визначає, як отримати підсумок із дозволених даних. Механізм визначає, звідки ці дані прийшли та куди піде результат. Тонка HTTP-обгортка може викликати правило й перетворити його результат на відповідь. Саме правило не повинно знати про статус 200 або метод send.

Це практичне застосування поділу відповідальностей та інверсії залежностей. Не кожна функція потребує інтерфейсу, контейнера й абстрактного базового класу. Почни з явних аргументів і невеликої поверхні контракту. Додаткова абстракція має спрощувати зміну або перевірку конкретної залежності.

## Композиція замість випадкової ієрархії

Успадкування описує підтип. Знижка та каталог не є підтипами розрахунку: вони є його складниками. Передавання функцій дозволяє незалежно замінювати кожен складник без множення класів на кшталт DiscountedCachedPremiumQuote.

Функція залежності теж може помилитися. Не підміняй таку помилку нульовою ціною. Перевір контракт повернутого значення, відхили неправильні дані та залиш контекст помилки для викликача.

У лабораторній однакова quote має працювати з різними каталогами й правилами знижки. Окремі екземпляри фабрики не ділять змінну конфігурацію, а вихідні позиції кошика залишаються незмінними.
