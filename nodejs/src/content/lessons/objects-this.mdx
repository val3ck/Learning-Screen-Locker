## this визначається викликом

У звичайної функції this залежить від способу виклику. У виразі reporter.log() отримувачем є reporter. Якщо дістати метод у змінну та викликати її окремо, попередній об’єкт не переноситься разом із функцією. ES-модулі працюють у strict mode, тому звичайний відокремлений виклик має this зі значенням undefined.

~~~js
const reporter = {
  prefix: 'api',
  log(message) { return this.prefix + ': ' + message; }
};
console.log(reporter.log('ready')); // api: ready
const callback = reporter.log;
// callback('ready') втратить отримувача
const stable = reporter.log.bind(reporter);
console.log(stable('ready')); // api: ready
~~~

Пройди приклад: властивість log містить функцію; читання властивості саме по собі не створює постійного зв’язку з reporter. bind повертає нову функцію із зафіксованим this. Оригінал залишається незмінним. call викликає функцію з окремими аргументами; apply приймає список аргументів масивом.

`bind` фіксує **об’єкт**, а не поточне значення його полів. Після `const stable = reporter.log.bind(reporter)` зміни `reporter.prefix = 'worker'`: наступний `stable('ready')` поверне `worker: ready`. Навіть `stable.call({ prefix: 'fake' }, 'ready')` не замінить уже прив’язаний контекст. Спробуй обидва виклики в консолі й поясни різницю між посиланням на об’єкт і знімком значення.

## Стрілкова функція має інше правило

Стрілка не отримує власний this, а використовує його з навколишнього лексичного середовища. Стрілка у звичайному літералі об’єкта не означає «this цього об’єкта». Натомість стрілкове поле класу створюється під час побудови екземпляра й захоплює його контекст.

Можна також прибрати залежність від this через замикання. Вибір залежить від API та життєвого циклу. Методи прототипу спільні між екземплярами; bind у конструкторі створює окрему функцію на екземпляр, але робить її безпечною для передачі як callback.

Порівняй дві реалізації за пам’яттю та зручністю: метод прототипу існує в одному екземплярі на клас, але при передаванні його часто треба прив’язати; стрілкове поле або `bind` у конструкторі створює функцію для кожного об’єкта. Це не вибір «правильного синтаксису» назавжди — перевіряй, чи справді метод передається як callback.

## На межі з чужим кодом

Обробник події, таймер або бібліотека вирішує, як викликати отриману функцію. Передавай метод так, щоб його контракт не залежав від невідомого отримувача. Водночас зберігай посилання на створений callback, якщо пізніше треба зняти підписку: повторний bind створить іншу функцію.

У лабораторній Reporter має записувати в ін’єктований write. Його log повинен працювати однаково через екземпляр, після деструктуризації та з чужим call. Так тестується поведінка на реальній межі передавання функцій.
