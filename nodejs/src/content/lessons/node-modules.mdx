## Модуль не повинен запускати весь застосунок

Модульний код простіше перевіряти, коли імпорт оголошує функції, а entrypoint виконує запуск. Якщо імпорт сервера одразу відкриває порт, кожний тест мусить прибирати цей побічний ефект. Функція `createApp` або `createServer` дозволяє відкласти запуск до явного рішення entrypoint.

Node підтримує ESM і CommonJS. Для `.js` значення `type` в найближчому `package.json` впливає на формат модуля; `.mjs` явно позначає ESM, `.cjs` — CommonJS. В ESM використовуємо `import` та `export`, і для відносних Node-імпортів важливі коректні розширення зібраних файлів.

```js
// config.mjs
export function loadConfig(env) {
  const port = Number(env.PORT ?? '3000');
  if (!Number.isInteger(port) || port < 1 || port > 65535) {
    throw new RangeError('Некоректний PORT');
  }
  return { port };
}

// main.mjs
// const config = loadConfig(process.env);
// const server = createServer();
// server.listen(config.port);
```

Приклад показує розділення відповідальності, але для практики перевір також текстовий формат: `Number('')` і числовий запис через експоненту можуть суперечити обраному контракту. Саме тому спочатку визначаємо допустимі рядки, а вже потім перетворюємо значення.

## Конфігурація — ще одна межа вводу

Змінні середовища надходять як текст. Типізація `port: number` з’являється лише після перевірки й перетворення. Зручно виконати це один раз на старті та передавати готовий config потрібним модулям. Помилка конфігурації тоді зупинить запуск одразу, а не проявиться після першого користувацького запиту.

Прикладові значення зберігай у `.env.example`, справжні секрети — поза Git. Не виводь весь `process.env` у лог: він може містити паролі й токени. Для діагностики склади окремий безпечний опис дозволених полів.

У тесті передай звичайний об’єкт `env`, не змінюючи глобальне середовище процесу. Так сценарії неправильного порту та невідомого режиму залишаться незалежними й відтворюваними.
