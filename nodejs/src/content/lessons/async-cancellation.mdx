## Promise не має універсальної кнопки stop

Якщо Promise.race поєднує запит і таймер, завершення таймера лише визначає результат очікування. Сам запит може далі використовувати сокет, пам’ять і зовнішній сервіс. Реальне скасування потребує співпраці операції.

AbortController створює сигнал; abort змінює його стан і повідомляє підписників. Сигнал передають API, яке підтримує скасування.

~~~js
const controller = new AbortController();
const request = fetch('https://example.com/data', {
  signal: controller.signal
});
controller.abort(new Error('Користувач змінив сторінку'));
await request.catch(error => console.log(error.message));
~~~

Це приклад роботи з мережею, а не команда для лабораторної. Там використовуємо ін’єктовану операцію без зовнішніх запитів. Вона отримує сигнал і сама завершує роботу з його причиною.

## Життєвий цикл сигналу

Скасований сигнал не можна «скинути». Наступний виклик із ним має одразу побачити aborted. Для власного API перевіряй signal.throwIfAborted перед стартом; інакше listener, доданий запізно, може не отримати вже минулу подію.

AbortSignal.any поєднує кілька сигналів: достатньо скасування одного. Так зовнішнє бажання користувача й внутрішній timeout мають спільний шлях. Причина допомагає відрізняти TimeoutError, навмисне скасування та звичайну помилку сервісу.

## Ресурс належить тому, хто його створив

Таймер очищається в finally незалежно від успіху або помилки. Власні listeners треба знімати після завершення, якщо вони ще потрібні довгоживучому об’єкту. Сервери, потоки й підключення теж мають явне завершення; повернення з функції саме по собі їх не закриває.

Таймер Node має власний діапазон затримки: надто велике значення не означає нескінченне очікування. У вправі явно обмежуємо затримку максимумом 2147483647 мілісекунд.

Контракт runWithTimeout у лабораторній передає об’єднаний сигнал. Якщо операція його ігнорує, функція не може примусово зупинити довільний JavaScript-код. Це важлива межа можливостей, а не причина приховувати сигнал.

Під час перевірки успіху використай великий timeout: програма має завершитися швидко, бо таймер очищено. Для відмови дочекайся самої події скасування; не перевіряй, що вона сталася рівно через певну кількість мілісекунд.
